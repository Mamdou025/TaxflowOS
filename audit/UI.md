### Chat-as-layer — ambient AssistantPanel + shared assistant core [2026-07-15]
The assistant stopped being **a place you navigate to** and became **a layer that follows you**. The orb no longer routes to `/`; it **toggles a docked `AssistantPanel`** that overlays whatever page you're on. The `/` route stays a full-screen **focus mode** for long sessions.

- **`components/assistant/use-assistant.tsx`** [LIVE] — the shared **brain**. A hook that registers the CopilotKit tools + readable context (moved verbatim out of `ChatWorkspace`: `openPage`/`focusAnchor`/`editField`/`closePage`/`closeAll`/`openWorkflowBuilder`/`runWorkflow`/`showWorkflowElement` + `useCopilotReadable` for open pages & the active run) and owns the conversation-launch state (`say`/`newChat`/`showHero`), the composer search/tools/attach handlers, the pinned inline cards, and the launcher actions. Also registers **`generateUI`** (OpenUI in-chat — see the GenUI section) and exposes **`composerCommands`** — a curated `@`-menu catalog of "build functions" (open worksheet / edit-fx inline / show FAPI source·output / run FAPI·roulement / generate-UI presets) so a capability can be invoked by name without knowing the vocabulary; each command runs the most reliable path (a launcher directly, else `say()` a canned phrase — GenUI commands `say('Generate this view: …')` → `generateUI`). Also runs an **orphaned tool-call self-heal** (idle-gated `useCopilotMessagesContext` prune) so an interrupted tool call can't poison every followup with "Tool result is missing …". Returns one `Assistant` object.
- **`components/assistant/assistant-thread.tsx`** [LIVE] — the presentational **chat column** shared by both surfaces: run pill · hero→conversation transition · pinned field/element cards · **pinned run cards** (deterministically-launched runs, rendered outside the `<CopilotChat>` message stream via the exported `RunWorkflowRender`) · `<CopilotChat>` with the Aside slots. Takes `{ assistant, variant: 'focus' | 'docked' }` (docked = compact hero, narrower paddings). `CHAT_THEME` / `NEU_*` / `INSTRUCTIONS` moved here.
- **`components/assistant/assistant-panel.tsx`** [LIVE] — the ambient docked card (`fixed`, right edge, `top:64 bottom:16 right:16`, `width min(420px,94vw)`, `z-45`). Header = ✦ Assistant · **Maximize2** (→ `/` focus mode) · **X** (close). Slides in/out on `assistantOpenAtom` (transform + opacity; `pointer-events:none` when closed). **Returns null on `/`** so focus mode owns the assistant there.
- **Single tool registration invariant:** `AssistantPanel` (all routes but `/`) and `ChatWorkspace` (only `/`) **never mount together**, so `useAssistant()` — and thus the CopilotKit actions — register exactly once. Verified via Playwright: on `/` there is no docked panel and no orb; the tools live in focus mode.

### Open-ended generative UI — OpenUI [in-chat bridge LIVE 2026-07-16; data still sample, no writeback]
Distinct from the CopilotKit actions above (which render a **fixed** component per registered action). This surface lets the model **compose arbitrary UI from a prompt** out of a registered vocabulary.
- **`app/genui-lab/page.tsx`** [WIP] — standalone demo: a prompt box + example chips → POST `/api/genui` → accumulates the streamed OpenUI Lang string → `<Renderer library={genuiLibrary} response=… isStreaming=…>` mounts real components live. `stripFences()` guards against markdown fences. A `<details>` shows the raw OpenUI Lang. **Preset entry [2026-07-16]:** a mount `useEffect` reads `?p=<prompt>` from the URL and auto-runs it, so the assistant's `@ Generate…` commands land here with the prompt prefilled and rendered.
- **`lib/genui/library.tsx`** — the vocabulary: OpenUI's 54 built-ins (`openuiLibrary`: BarChart/LineChart/PieChart/Table/Card/Input/Select/Tabs/…) **+** a custom `TaxMetric` KPI tile via `defineComponent` (Zod-typed props, our styling). The model can compose both together.
- **`app/api/genui/route.ts`** — streams OpenUI Lang from OpenAI. **Does NOT import OpenUI** (react-lang calls `React.createContext` at load → fails in the RSC route runtime); it reads the pre-generated `lib/genui/system-prompt.txt`. **Reliability [2026-07-16]:** defaults to **`gpt-4.1`** (`GENUI_MODEL` to override; kept separate from CopilotKit's `OPENAI_CHAT_MODEL` so tuning the generator can't regress chat) — it emits the DSL far more reliably than gpt-4o, which narrated Markdown for short prompts. The stream **sniffs the first line** (`looksLikeLang`); if it's prose it self-heals with **one non-streaming retry** using a `HARD_STEER` message, so a prose slip renders correct UI instead of nothing / a Markdown table. **Literal-values steer [2026-07-16]:** the `STEER` block also forbids JS expressions in value slots (`.toFixed`, arithmetic, member access, undefined refs) — OpenUI Lang doesn't evaluate them and leaks internals (a tile showing `function toFixed() { [native code] }`); the model must pre-format numbers into string literals and bind editable fields to a `$var` defined as a literal.
- **`scripts/gen-genui-prompt.cjs`** (`pnpm genui:prompt`) — regenerates that prompt file from the library. Re-run whenever the library changes; the `TaxMetric` def here must mirror `library.tsx`.
- **Verified (Playwright):** "3 KPI tiles + a dividends bar chart" renders live on `/genui-lab` — custom `TaxMetric` tiles (FAPI $1.24M +12% green) + built-in `BarChart` together; no Renderer errors.
- **In-chat bridge (`renderUI`) [LIVE, 2026-07-16]:** OpenUI generation now runs **inside the assistant**, not just the lab. `use-assistant.tsx` registers a **`generateUI`** CopilotKit action (parameter `prompt`); its `render` mounts **`components/assistant/genui-render.tsx`** (`GenUIRender`) — a client component that POSTs the prompt to `/api/genui`, streams the OpenUI Lang, and feeds `<Renderer library={genuiLibrary}>` inside a light card (legible on the dark chat). **Chat-cohesive design [2026-07-16]:** rendered artifacts read as one **light "result" surface** on the dark chat. OpenUI defaults to a **dark** theme (its cards rendered dark inside the light wrapper — ugly clash), so `GenUIRender` wraps `<Renderer>` in **`<ThemeProvider mode="light">`** (`@openuidev/react-ui`) → cards render light and blend with the wrapper, `TaxMetric`, and the run-flow renders. ### Page ⇄ Chat contract — command any page + summon it into the chat [2026-07-17]

- **Location:** `components/ai-elements/canvas.tsx` (initialized here) + `components/workflow/` (usage)
- **Technology:** `@xyflow/react` v12
- **Background:** `bg-transparent` — background is owned by `PersistentCanvas` wrapper
- **Grid:** `BackgroundVariant.Lines`, `color: rgba(255,255,255,0.055)`, gap 28px, lineWidth 0.5 — subtle white lines on dark canvas
- **No AmbientOrbs:** removed (2026-06-07) — rotating orb circles removed from canvas background
- **Legend box:** Dark styling (`rgba(26,26,32,0.88)` bg, `rgba(255,255,255,0.08)` border, white/55 + white/35 text)
- **Features:**
  - Drag/drop block placement
  - Handle-based connection drawing
  - Right-click context menu (`workflow-context-menu.tsx`)
  - Pending connection state
  - AI prompt panel integration (`prompt.tsx`)
  - Undo/redo keyboard hooks
  - Minimap (conditional on `showMinimapAtom`)
  - Viewport fit on workflow load
  - Animated edge transitions

### `persistent-canvas.tsx`
- **Location:** `components/workflow/persistent-canvas.tsx`
- **Role:** Fixed full-viewport canvas layer behind all page content; handles background color transition
- **Mount transition:** Background starts `#eaeaef` (matching homepage), fades to `#18181c` over 900ms after 60ms delay — seamless navigation from homepage to builder
- **Only active on:** `/builder` and `/workflows/*` — renders `null` on all other routes

## Design System Notes

### Neumorphic Theme (`app/globals.css`)
- CSS variables `--neu-bg` (oklch 0.89 light / 0.14 dark), `--neu-text`, `--neu-text-muted`, `--neu-shadow-up`, `--neu-shadow-menu`, `--neu-shadow-press` defined for light and dark modes — tighter 3–4px offsets, moderate opacity (no glow)
- `.neu-surface` — raised panel (navbar, nav pill): solid bg + dual soft shadow, no border
- `.neu-menu` — floating dropdown/context menu: same bg with smaller shadow offsets, no border
- `[data-highlighted]` inside `.neu-menu` gets an inset pressed shadow for keyboard/pointer focus
- Applied to: `workflow-toolbar.tsx` panels, `dropdown-menu.tsx`, `context-menu.tsx`

## UI State Summary (atoms that drive UI)

| Atom | Drives |
|---|---|
| `selectedNodeAtom` | Inspector panel block view |
| `selectedEdgeAtom` | Inspector panel edge view |
| `propertiesPanelActiveTabAtom` | Active inspector tab |
| `showMinimapAtom` | Minimap visibility |
| `rightPanelWidthAtom` | Inspector panel width |
| `activeRightPanelAtom` | Which right panel is open (null = closed) |
| `isSidebarCollapsedAtom` | Left sidebar state |
| `isPanelAnimatingAtom` | Panel slide animation (managed by RightPanelShell) |
| `isExecutingAtom` | Run button loading state |
| `isGeneratingAtom` | AI prompt loading state |
| `hasUnsavedChangesAtom` | Save button state |
| `showClearDialogAtom` | Clear confirmation dialog |
| `showDeleteDialogAtom` | Delete confirmation dialog |
